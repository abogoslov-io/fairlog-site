Data Processing Addendum

Fairlog is operated by PE Anton Bogoslov Igor (Individual Entrepreneur, Armenia).

Version 0.2 · August 2026 · Controller: the customer · Processor: PE Anton Bogoslov Igor (Individual Entrepreneur, Armenia) · Sub-processor: Atlassian (Forge platform)

Draft under legal review. The published version may change before the Marketplace listing goes live.

1. Subject and duration

Processing is limited to what the App's functions require (billing reports and statements based on Jira worklogs) for the duration of the subscription.

2. Data categories

  • Atlassian user identifiers (accountId), display names, avatar references.
  • Working time: worklogs (date, duration, issue, author) and their billable/client marks.
  • Organisational financial parameters: rates (including person-linked rates, which are personal data) and statement amounts.

Data subjects: users of the customer's Jira instance. No special categories of data are processed. No profiling, advertising, or model training takes place.

3. Storage, residency and security

All data is stored in Atlassian Forge hosted storage (KVS/SQL) within the customer's instance. Data residency applies automatically: if the customer's Atlassian product is pinned to a region, Forge hosts, pins and migrates the App's data in the same region (Forge Data residency documentation, July 2026). Access to rates and amounts is restricted to App roles (admin/finance) and enforced server-side. The Vendor has no direct access to customer data (no external servers, no egress); diagnostics rely on Forge platform logs that contain errors and identifiers only — no personal data content.

4. Sub-processors

Atlassian (Forge) is the only sub-processor. Changes are announced via release notes / the listing.

5. Data subject requests and deletion

Requests (access / deletion / anonymisation) for a specific accountId are fulfilled via the Vendor's support channel within 30 days. Deleted or anonymised: worklog-cache rows, person-linked rates, the App role. Snapshot lines of issued statements are anonymised (author replaced), as they constitute the organisation's financial records. A self-service "purge user data" admin button is planned for release 1.0.x. Upon app uninstallation, Forge hosted storage is retained for 28 days by Atlassian and then deleted.

6. Incidents

The Controller is notified of personal data breaches without undue delay; Atlassian is notified within 48 hours.

7. Audit

Upon request, the Vendor provides a description of security measures (this DPA, the Forge/Runs on Atlassian architecture note, lightweight CAIQ).
